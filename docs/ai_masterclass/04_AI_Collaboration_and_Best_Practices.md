# Chapter 4: 🤖 AI Collaboration & Best Practices

AI တွေ (ChatGPT, Claude, Cursor) က Code ရေးတဲ့ နေရာမှာ အံ့မခန်း မြန်ဆန်ပါတယ်။ ဒါပေမယ့် သူတို့ဟာ သင် ခိုင်းသလောက်ပဲ လုပ်ပေးနိုင်တဲ့ အလုပ်သမားတွေ (Junior Developers) ပါ။ ကောင်းမွန်တဲ့ Web App တစ်ခု ထွက်လာဖို့ဆိုရင် သင်ကိုယ်တိုင်က ပြတ်သားတဲ့ ဦးဆောင်သူ (Senior Developer) တစ်ယောက်လို တွေးခေါ်ခိုင်းစေတတ်ဖို့ လိုပါတယ်။

## ၁။ AI ကို ခိုင်းစေနည်း (Prompt Engineering for Coders)

ခိုင်းစေတဲ့ (Prompt) အပေါ် မူတည်ပြီး ရလာတဲ့ Code အရည်အသွေး ကွာခြားပါတယ်။

**❌ အမှား (Bad Prompt):**
> *"Web Panel လေး တစ်ခုလောက် ရေးပေး။ Login ပါရမယ်။ User တွေ ထည့်လို့ရရမယ်။"*
> (AI က သူတွေးချင်ရာ တွေးပြီး ပရောဂျက်ကြီး တစ်ခုလုံးကို ဖိုင်တစ်ဖိုင်တည်းမှာ ရှုပ်ပွအောင် ရေးပေးပါလိမ့်မယ်။ သင့်အတွက် နားလည်ဖို့ရော၊ ပြင်ဖို့ပါ ခက်သွားပါပြီ။)

**✅ အမှန် (Good Prompt - Context & Constraints):**
> *"ငါ Hysteria 2 VPN အတွက် Web Panel တစ်ခု ရေးချင်တယ်။ 
> **Tech Stack:** Backend ကို Python (FastAPI)၊ Frontend ကို HTML/JS အလွတ် (Vanilla)၊ Database ကို SQLite သုံးမယ်။
> **အခု ပထမဆုံးအဆင့်အနေနဲ့:** Backend အတွက် `main.py` ဖိုင် အခွံလေးနဲ့ `/api/users` ဆိုတဲ့ Endpoint လေး တစ်ခု အရင်ရေးပေးပါ။ Data တွေကို Database ထဲက မယူသေးဘဲ Dummy Array ထဲကနေပဲ အရင် ပြန်ပေးပါ။"*
> (ဒီလိုခိုင်းတဲ့အတွက် AI က အပိုင်းလိုက် (Incremental) သေသေချာချာ စနစ်တကျ ရေးပေးပါလိမ့်မယ်။)

## ၂။ ပြဿနာတက်ရင် AI နဲ့ ဘယ်လို ဖြေရှင်းမလဲ? (Debugging)

Code ရေးရင် Error တက်တာ သဘာဝပါ။ အရေးကြီးတာက AI ကို ဘယ်လို ပြန်မေးမလဲ ဆိုတာပါပဲ။

- **❌ "အလုပ်မလုပ်ဘူး"၊ "Error တက်နေတယ်" လို့ ဘယ်တော့မှ မပြောပါနဲ့။**
  - AI က မှန်းဆပြီး ပြင်ပေးပါလိမ့်မယ်။ တဖြည်းဖြည်းနဲ့ အကောင်းပါ ပျက်သွားနိုင်ပါတယ်။

- **✅ Log တွေကို ဖတ်ပြီး အတိအကျ ပြပါ။**
  - Backend မှာ Error တက်ရင် Terminal က (သို့) `journalctl -u hy2-panel.service -f` က ထွက်လာတဲ့ Error Message (ဥပမာ - `ValueError: Invalid hash`) အပြည့်အစုံကို Copy ကူးပြီး ပေးပါ။
  - Frontend မှာ Error တက်ရင် Browser မှာ F12 နှိပ်ပြီး `Console` ထဲက အနီရောင်စာကြောင်းတွေကို Copy ကူးပေးပါ။
  - *"ဒီမှာ Error တက်နေတယ်။ Terminal လော့ဂ်က {Log Text} လို့ ပြနေတယ်။ `main.py` ဖိုင်ရဲ့ လိုင်းနံပါတ် ၄၅ လောက်က ပြဿနာထင်တယ်။ ဘယ်လိုပြင်ရမလဲ စစ်ပေးပါ"* လို့ ခိုင်းပါ။

## ၃။ Code များကို သန့်ရှင်းသပ်ရပ်အောင် ရေးနည်း (Clean Code Principles)

AI က ရေးပေးတိုင်း ယူမသုံးပါနဲ့။ ရေရှည်မှာ ကိုယ်တိုင် ပြန်ဖတ်ရင် နားလည်အောင်၊ သူများလာဖတ်ရင် နားလည်အောင် AI ကို သပ်သပ်ရပ်ရပ် ရေးခိုင်းပါ။

1. **စကားပြောတတ်သော နာမည်များ (Descriptive Names):**
   - Function နာမည်ကို `def do_stuff():` လို့ မပေးခိုင်းပါနဲ့။ `def check_user_data_limit():` လို့ အတိအကျ ပေးခိုင်းပါ။
2. **Comment များ (Documentation):**
   - ရှုပ်ထွေးတဲ့ Logic တွေ ပါရင် AI ကို အမြဲတမ်း *"ဒီ Function ဘာလုပ်သလဲ ဆိုတာကို အထက်မှာ Docstring နဲ့ မြန်မာလို (သို့) အင်္ဂလိပ်လို ရှင်းပြပေးပါ"* လို့ တောင်းဆိုပါ။
3. **ဖိုင်များ ခွဲထုတ်ခြင်း (Modularity):**
   - ဖိုင်တစ်ဖိုင်တည်းမှာ စာကြောင်းရေ ၁၀၀၀ ကျော်လာရင် AI ကို *"ဒီ `main.py` ကြီးက ရှုပ်လာပြီ။ Authentication ပိုင်းကို `auth.py` ဆိုပြီး ဖိုင်သီးသန့် ခွဲထုတ်ပေးပါ။ Router တွေ သုံးပြီး ပြန်ချိတ်ပေးပါ။"* လို့ ခိုင်းပြီး သပ်သပ်ရပ်ရပ် စီမံပါ။

## ၄။ ဉာဏ်ရည်တုကို မှတ်ဉာဏ်ပေးခြင်း (Rules & Knowledge)

AI တွေ (ဥပမာ Cursor) မှာ သင့်ပရောဂျက်ရဲ့ အကြောင်းကို အမြဲတမ်း မှတ်မိနေအောင် `.cursorrules` (သို့) `ARCHITECTURE.md` လို ဖိုင်တွေ ဖန်တီးပေးထားသင့်ပါတယ်။

- အဲဒီဖိုင်တွေထဲမှာ သင့်ပရောဂျက်က ဘာ Database သုံးလဲ၊ ဘာ Library သုံးလဲ၊ လုံခြုံရေးအတွက် ဘာတွေ အမြဲစစ်ဆေးရမလဲ ဆိုတာကို ရေးထားလိုက်ရင် AI ဟာ ခိုင်းတိုင်း ခိုင်းတိုင်း အဲဒီဖိုင်ကို အရင်ဖတ်ပြီးမှ အလုပ်လုပ်တဲ့အတွက် အခြေခံအမှားတွေ လုံးဝ (လုံးဝ) ထပ်မလုပ်တော့ပါဘူး။
