# Chapter 1: 🏗️ System Architecture & Databases

Web App တစ်ခုကို မစတင်ခင် အရေးကြီးဆုံးက သူ့ရဲ့ ဖွဲ့စည်းပုံ (Architecture) ကို မြင်ယောင်တတ်ဖို့ပါ။ အိမ်တစ်လုံးဆောက်တဲ့အခါ အုတ်မြစ်၊ နံရံ၊ အမိုး ခွဲခြားစဉ်းစားရသလိုပါပဲ။

## ၁။ Web App ၏ ဖွဲ့စည်းပုံ (The 3 Pillars)

Web Application တိုင်းမှာ အဓိက မဏ္ဍိုင် (၃) ခု ရှိပါတယ်။

### A. Frontend (မျက်နှာစာ)
- **အလုပ်လုပ်ပုံ:** User တွေ တိုက်ရိုက်ထိတွေ့ရတဲ့ မျက်နှာပြင်ပါ။ Browser ပေါ်မှာ အလုပ်လုပ်ပါတယ်။ 
- **နည်းပညာများ:** HTML (အရိုးစု), CSS (အလှအပ), JavaScript (အသက်သွင်းခြင်း)။ တချို့ ကြီးမားတဲ့ App တွေမှာ React, Vue, Next.js လို Framework တွေ သုံးပါတယ်။
- **ကျွန်တော်တို့ ပရောဂျက်:** `static/index.html` တစ်ဖိုင်တည်းနဲ့ Frontend အကုန်လုံးကို ရေးသားထားပါတယ်။

### B. Backend (ဦးနှောက်)
- **အလုပ်လုပ်ပုံ:** Frontend ကနေ လှမ်းတောင်းတဲ့ အချက်အလက်တွေကို စဉ်းစားတွက်ချက်ပေးတဲ့ နေရာပါ။ လုံခြုံရေးတွေကို စစ်ဆေးပေးတယ်။ Database နဲ့ ချိတ်ဆက်ပေးတယ်။
- **နည်းပညာများ:** Python (FastAPI, Django), Node.js (Express), PHP (Laravel), Go, Java.
- **ကျွန်တော်တို့ ပရောဂျက်:** `main.py` မှာ Python ဖြင့် `FastAPI` ကို သုံးပြီး ရေးသားထားပါတယ်။ `FastAPI` က အရမ်းမြန်ဆန်ပြီး ရေးရလွယ်ကူလို့ ယခုခေတ်မှာ အရမ်းခေတ်စားပါတယ်။

### C. Database (မှတ်ဉာဏ်တိုက်)
- **အလုပ်လုပ်ပုံ:** အချက်အလက် (Data) တွေကို အမြဲတမ်း တည်မြဲအောင် သိမ်းဆည်းပေးတဲ့ နေရာပါ။
- **နည်းပညာများ:** SQLite, PostgreSQL, MySQL, MongoDB.
- **ကျွန်တော်တို့ ပရောဂျက်:** `database.db` ဖိုင်ကို `SQLite` သုံးပြီး ဖန်တီးထားပါတယ်။

## ၂။ Database ရွေးချယ်ခြင်း (How to choose the right DB)

Database တွေ အများကြီးရှိတဲ့အထဲက ကိုယ့် App အတွက် ဘယ်ဟာ အသင့်တော်ဆုံးလဲ ဆိုတာ ဆုံးဖြတ်တတ်ဖို့ အရေးကြီးပါတယ်။

### ၁. SQLite (ပေါ့ပါး၊ ရိုးရှင်း)
- **သဘောတရား:** ဆာဗာ သီးသန့်မလိုဘဲ ဖိုင် (File) အနေနဲ့ သိမ်းတာပါ။
- **ဘယ်အချိန်သုံးမလဲ:** အခုလို Hysteria Panel လိုမျိုး၊ လူသုံး သိပ်မများတဲ့စနစ်၊ Data သိပ်မများတဲ့ စနစ် (Users ထောင်ဂဏန်းလောက်အထိ) အတွက် အကောင်းဆုံးပါ။ အရမ်းပေါ့ပါးပြီး Backup လုပ်ရတာ (ဖိုင်ကို Copy ကူးလိုက်ရုံမို့) လွယ်ကူပါတယ်။
- **အားနည်းချက်:** User သိန်းချီပြီး တစ်ပြိုင်နက်တည်း အသုံးပြုလာရင် နှေးသွားနိုင်ပါတယ်။

### ၂. PostgreSQL / MySQL (ခိုင်မာ၊ ကြီးမား)
- **သဘောတရား:** သီးသန့် Database Server ကြီး လိုအပ်ပါတယ်။ (Relational DB)
- **ဘယ်အချိန်သုံးမလဲ:** E-commerce Web App တွေ၊ လူသုံးများတဲ့ Social Media လို App တွေ၊ Data အရမ်းများပြီး ချိတ်ဆက်မှု (Relationships) တွေ ရှုပ်ထွေးတဲ့ စနစ်တွေအတွက် မဖြစ်မနေ သုံးရပါတယ်။ ပရော်ဖက်ရှင်နယ် အကျဆုံးပါ။
- **အားနည်းချက်:** ဆာဗာမှာ Memory (RAM) ပိုစားပါတယ်။ Setup လုပ်ရတာ ရှုပ်ထွေးပါတယ်။

### ၃. MongoDB (ပြောင်းလွယ်ပြင်လွယ်)
- **သဘောတရား:** NoSQL လို့ခေါ်ပါတယ်။ ဇယား (Table) တွေနဲ့ မသိမ်းဘဲ Document (JSON ဖိုင်ပုံစံ) နဲ့ သိမ်းတာပါ။
- **ဘယ်အချိန်သုံးမလဲ:** Chat Application တွေ၊ Data ပုံစံ အမြဲပြောင်းလဲနေတတ်တဲ့ စနစ်တွေအတွက် ကောင်းပါတယ်။

**💡 AI ကို ခိုင်းတဲ့အခါ (Pro Tip):** 
"Database ချိတ်ပေးပါ" လို့ လွယ်လွယ်မခိုင်းပါနဲ့။ *"ဒီ App က သိပ်မကြီးလို့ SQLite ပဲ သုံးမယ်၊ ဇယား (Table) ဖွဲ့စည်းပုံကို သေချာဆွဲပေးပါ"* (သို့မဟုတ်) *"ဒီ App က E-commerce ဖြစ်လို့ PostgreSQL နဲ့ ရေးမယ်၊ Database Migration အတွက် Alembic လိုမျိုး သုံးပေးပါ"* လို့ တိတိကျကျ ခိုင်းပါ။

## ၃။ အခြေခံအမှားများ မဖြစ်စေရန်

1. **Business Logic ကို Frontend မှာ မထားပါနဲ့:** 
   ဥပမာ - User တစ်ယောက် Data ဘယ်လောက်ကျန်လဲ တွက်တဲ့အလုပ်ကို Frontend (JS) ထဲမှာ မရေးရပါဘူး။ Browser မှာ သွားတွက်ရင် Hacker တွေက Data ကို ပြင်ပစ်လို့ ရပါတယ်။ တွက်ချက်မှု အားလုံးကို **Backend** ကပဲ လုပ်ရပါမယ်။ Frontend က ပြသပေးရုံသက်သက်ပဲ လုပ်ရပါမယ်။

2. **Database ကို တိုက်ရိုက် မချိတ်ပါနဲ့:**
   Frontend ကနေ Database ဆီကို တိုက်ရိုက်ချိတ်တာမျိုး ဘယ်တော့မှ (လုံးဝ) မလုပ်ရပါဘူး။ ကြားခံ Backend (API) ကနေပဲ သွားရပါမယ်။
